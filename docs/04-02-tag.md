# 04-02 `tag`

## 1. この項目で学ぶこと

この項目では、`tag` を使って特定コミットへ目印を付ける基本を学ぶ。

この項目で押さえることは次のとおり。

- tag の役割
- lightweight と annotated の考え方
- バージョン目印としての利用

---

## 2. 事前に理解しておきたいこと

tag は、特定のコミットに対して「ここが基準点」「ここがリリース点」といった目印を付けるために使う。

今回は次の 3 つを確認する。

- lightweight tag を現在の HEAD に付ける
- annotated tag を現在の HEAD に付ける
- 特定の過去コミットに tag を付ける

---

## 3. 主要コマンド

```bash
git tag
git tag <tag-name>
git tag -a <tag-name> -m "message"
git tag <tag-name> <commit-hash>
git show <tag-name> --no-patch
git log --oneline --graph --decorate --all
```

### コマンドの役割

- `git tag`  
  タグ一覧を見る

- `git tag <tag-name>`  
  lightweight tag を作る

- `git tag -a <tag-name> -m "message"`  
  annotated tag を作る

- `git tag <tag-name> <commit-hash>`  
  特定コミットに tag を付ける

- `git show <tag-name> --no-patch`  
  タグがどのコミットを指しているか確認する

## 5. 手を動かす演習

### 演習 1: タグ用のコミットを作る

- Markdown ファイルを更新して commit する

### 演習 2: lightweight tag を付ける

- HEAD に lightweight tag を付ける
- `git tag` で確認する

### 演習 3: annotated tag を付ける

- さらに 1 コミット作る
- annotated tag を付ける
- `git show` で確認する

### 演習 4: 特定の過去コミットへ tag を付ける

- `git log --oneline` で対象コミットを探す
- そのハッシュに対して tag を付ける
- `git log --decorate` で見え方を確認する

---

## 6. 実行後に確認すること

- tag はコミットへの目印である
- lightweight tag と annotated tag の作り方が違う
- tag は特定の過去コミットにも付けられる
- `git log --decorate` でタグの位置が見える

---

## 7. 観察ポイント

- `git tag` で一覧が見える
- `git show <tag-name> --no-patch` で指しているコミットが分かる
- `git log --decorate` でタグ名がコミット横に表示される

---

## 8. よくあるミス

- tag を branch と同じように考える
- どのコミットに付けたか確認しない
- lightweight と annotated の違いを見ない

---

## 9. まとめ

この項目では、履歴上のコミットへ tag を付ける基本を確認した。  
tag は「履歴の目印」として使うと整理しやすい。
