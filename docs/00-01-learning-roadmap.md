# 00-01 学習ロードマップ

## 1. この項目で学ぶこと

この項目では、これから進める Git / GitHub 学習全体の方針と進め方を整理する。  
このドキュメントは、学習開始前に全体像を把握し、今どこを学んでいるのかを見失わないための土台として使う。

この項目で押さえることは、主に次のとおり。

- このリポジトリの目的
- 今回の学習方針
- 到達目標
- 番号体系の見方
- docs と practice の役割
- 全学習項目の一覧

---

## 2. このリポジトリの位置付け

このリポジトリは、**Git / GitHub を学習するための実験・学習用リポジトリ** である。

そのため、このリポジトリでは次のことを優先する。

- Git の概念理解
- CLI による基本操作の習得
- 状態変化の観察
- コンフリクトや復旧などの実務で詰まりやすい現象の体験
- GitHub を使った基本的な運用フローの理解

---

## 3. このリポジトリの目的

このリポジトリの目的は、Git / GitHub を一から学び、実務でよく使う基本操作と考え方を体系的に理解することにある。

特に次の状態を目指す。

- Git の基本操作を CLI で行える
- branch / merge / conflict / undo / PR を説明できる
- ローカル操作とリモート運用の流れを理解している
- 詰まっても状態を見ながら調べて進められる

---

## 4. 今回の学習方針

今回の学習では、次の方針を重視する。

### 4-1. 基礎から順に積み上げる

最初から応用操作に進まず、まずは次を順に固める。

- Git と GitHub の違い
- ローカルでの基本操作
- 履歴の見方
- ブランチとマージ
- 取り消しと復旧
- リモートと GitHub 運用
- rebase や総合演習

### 4-2. 広く一通り触る

理解を深めることは大事だが、最初の段階では **全体像に一通り触れること** も重視する。

### 4-3. 知識と演習をセットにする

各学習項目では、説明だけで終わらず、必ず実際の操作や状態確認を行う。
docs は説明資料ではなく、**再現可能な演習手順書** として残す。

### 4-4. CLI 中心で学ぶ

今回は、VS Code の GUI 操作ではなく、CLI の操作で理解を深める。
GUI は便利だが、CLI で状態を把握できるようになると、Git の理解が安定しやすい。

---

## 5. 到達目標

今回の到達目標は次のとおり。

- Git の基本操作を CLI でできる
- `branch` / `merge` / `conflict` / `undo` / `PR` を言葉でも説明できる
- Git のローカル操作と GitHub のリモート運用の流れを理解している
- 実務でよく使う Git / GitHub の基本知識・基本操作を一通り把握している
- 詰まっても、状態を見ながら調べて自分で進められる

---

## 6. 番号体系の見方

このリポジトリでは、学習計画・docs・演習管理を同じ番号体系で統一する。

### 形式

- `大項目-小項目`

### 例

- `00-01`
- `01-03`
- `02-04`
- `05-02`

### ルール

- 先頭 2 桁 = 学習の大項目
- 後半 2 桁 = その中の小項目
- `00-*` は補助ドキュメント用

### この番号で統一するもの

- 学習計画上の項目番号
- docs のファイル名
- practice 側の演習識別子
- 演習用ファイル名の先頭番号

---

## 7. docs と practice の役割

### docs の役割

`docs/` には、各学習項目の説明と演習手順を残す。
内容は次のようなものを含む。

- この項目で学ぶこと
- 主要コマンド
- 演習で使用するファイル
- 手を動かす演習
- 実行後の確認ポイント
- よくあるミス
- まとめ
- 次の項目とのつながり

### practice の役割

`practice/` には、実際に編集・差分確認・マージ・競合・復旧などに使うファイルを置く。
今後は、HTML / CSS / JS / JSON などのテキストファイルを中心に使っていく。

## 8. 全学習項目一覧

このリポジトリでは、次の順で学習を進める。

### 00. 補助ドキュメント

- `00-01` 学習ロードマップ

- `06-03` 総合演習シナリオ
