# 04-03 `cherry-pick`

## 1. この項目で学ぶこと

この項目では、`cherry-pick` を使って特定のコミットだけを別ブランチへ取り込む基本を学ぶ。

この項目で押さえることは次のとおり。

- cherry-pick とは何か
- どんな時に使うか
- 乱用しない考え方
- 履歴の見え方

---

## 2. 事前に理解しておきたいこと

`cherry-pick` は、あるブランチの変更を丸ごと merge するのではなく、**特定のコミットだけ** を別ブランチへ取り込みたいときに使う。

たとえば次のような場面で使うことがある。

- バグ修正 1 件だけを別ブランチにも反映したい
- 必要なコミットだけ選んで取り込みたい
- merge するほどではないが、特定修正だけ欲しい

ただし、便利だからといって多用すると、どのブランチに何がどう入ったか分かりにくくなることがある。  
そのため、基本は merge や通常のブランチ運用を優先し、必要な場面で限定的に使う。

---

## 3. 主要コマンド

```bash
git cherry-pick <commit-hash>
git log --oneline --graph --decorate --all
git status
git branch
```

### コマンドの役割

- `git cherry-pick <commit-hash>`  
  指定したコミットだけを現在のブランチへ取り込む

- `git log --oneline --graph --decorate --all`  
  どのコミットがどこに入ったか確認する

- `git status`  
  現在の状態を確認する

- `git branch`  
  現在どのブランチにいるか確認する

## 5. 手を動かす演習

### 演習 1: source 用ブランチと target 用ブランチを作る

- `sandbox/cherry-pick-demo` を土台にする
- `feature/cherry-source` を作る
- `feature/cherry-target` を作る

### 演習 2: source 側で複数コミットを作る

- 同じファイルに対して 2 回コミットする
- 取り込みたいコミットと、取り込まないコミットを分ける

### 演習 3: target 側で特定コミットだけ取り込む

- `feature/cherry-target` に切り替える
- `git cherry-pick <commit-hash>` を実行する

### 演習 4: 履歴とファイル内容を確認する

- `log --graph` で履歴を見る
- 対象の変更だけが取り込まれていることを確認する

---

## 6. 実行後に確認すること

- cherry-pick は特定コミットだけを取り込む
- merge と違って、ブランチ全体を統合するわけではない
- source 側の全コミットが target に入るわけではない
- `log --graph` とファイル内容で結果を確認できる

---

## 7. 観察ポイント

- cherry-pick 後、target 側に新しいコミットが増える
- source 側の別コミットは target に入らない
- 同じ変更内容でも、コミットとしては target 側に新しく積まれる

---

## 8. よくあるミス

- merge と同じ感覚で使う
- どのコミットを取り込むか確認せず実行する
- source 側の全部が入ると思い込む
- 履歴を確認しないまま終える

---

## 9. まとめ

この項目では、`cherry-pick` によって特定コミットだけを別ブランチへ取り込む基本を確認した。  
便利な操作だが、基本は通常のブランチ運用を優先し、必要な場面で限定的に使う。
