# 01-01 Git と GitHub の全体像

## 1. この項目で学ぶこと

この項目では、Git と GitHub の役割の違いと、今後の学習で押さえるべき全体像を整理する。

この項目で押さえることは次のとおり。

- バージョン管理とは何か
- Git とは何か
- GitHub とは何か
- Git と GitHub の違い
- SVN と Git の考え方の違い
- ローカル作業とリモート作業の違い

---

## 2. 事前に理解しておきたいこと

今後の学習では、まず **Git** と **GitHub** を分けて理解することが大切である。

- Git = バージョン管理の仕組みそのもの
- GitHub = Git のリポジトリを共有・公開・レビュー運用するためのサービス

この区別が曖昧だと、ローカルで何をしていて、GitHub 上で何をしているのかが分かりにくくなる。

---

## 3. 学ぶ内容

### バージョン管理とは何か

ファイルの変更履歴を管理し、次のことをできるようにする仕組みである。

- いつ何を変更したかを残す
- 変更前の状態に戻る
- 差分を確認する
- 作業を分岐して進める
- 変更を統合する

### Git とは何か

Git は、ローカルで履歴管理・分岐・統合・復旧などを行えるバージョン管理システムである。  
今後の学習では、まず Git のローカル操作を中心に学ぶ。

### GitHub とは何か

GitHub は、Git のリポジトリをホストし、共有・レビュー・Pull Request・履歴の可視化などを行うためのサービスである。  
GitHub 自体が Git ではない。

### Git と GitHub の違い

- Git は仕組み
- GitHub はサービス

この違いを前提に、今後は次のように整理する。

- Git で行うこと  
  `init` / `status` / `add` / `commit` / `branch` / `merge` など

- GitHub で行うこと  
  リモートリポジトリ作成 / Pull Request / merge / ブランチ削除 など

### SVN と Git の違い

SVN は中央集権型として理解すると整理しやすい。  
一方 Git は、ローカル側にも履歴があり、ブランチやコミットをローカルで柔軟に扱いやすい。

今回の学習では、特に次の感覚へ慣れることが重要になる。

- ローカルで履歴を作る
- ブランチを軽く切る
- 状態を `status` や `log` で読む
- GitHub へはあとから push する

### ローカル作業とリモート作業の違い

今後の学習では、次の区別を意識する。

- ローカル作業  
  自分の PC 上で行う Git 操作

- リモート作業  
  GitHub 上のリポジトリや PR で行う操作

---

## 4. よくあるミス・混乱ポイント

### Git と GitHub を同じものだと思う

最初にここを分けて理解する。

### GitHub に上げないと commit ではないと思う

commit はローカルでも作れる。  
push はそのあとである。

### SVN と同じ感覚で考えすぎる

Git はローカル側に履歴があることが大きな違いである。
